# TPT Construction Design Document

## Project Identity

- Organization: `tpt-solutions`
- Repository: `tpt-construction`
- Crate prefix: `tpt-c-`
- Primary language: Rust
- License: `MIT OR Apache-2.0`
- Related substrates:
  - `tpt-math`
  - `tpt-engineering`

---

## 1. Purpose

`tpt-construction` is a modular Rust workspace providing reusable libraries for the construction industry.

Its goal is to eventually provide crate coverage for at least 80% of the construction software domain, including:

- BIM / IFC
- estimating
- quantity takeoff
- scheduling
- project controls
- field management
- civil / earthwork
- equipment telemetry
- safety
- documents / contracts
- facility management
- digital twins
- WebAssembly tooling

The repository acts as the construction-specific layer on top of:

```text
tpt-math
tpt-engineering
tpt-construction
```

## 3. Licensing Strategy

Each crate is released as:

```toml
license = "MIT OR Apache-2.0"
```

Use `OR`, not `AND`.

Correct:

```toml
license = "MIT OR Apache-2.0"
```

Incorrect for dual licensing:

```toml
license = "MIT AND Apache-2.0"
```

The repository should contain:

```text
LICENSE-MIT
LICENSE-APACHE
```

The README should state:

```text
Licensed under either of MIT or Apache-2.0 at your option.
```

---

## 4. MIT Chain Policy

Although the crates are dual-licensed as `MIT OR Apache-2.0`, the project should preserve an MIT-selectable dependency chain where possible.

### Default policy

Allowed dependencies:

```text
MIT
MIT OR Apache-2.0
Unicode-DFS-2016
Unicode-3.0
```

Allowed with review:

```text
Apache-2.0
BSD-2-Clause
BSD-3-Clause
ISC
Zlib
```

Banned dependencies:

```text
GPL-2.0
GPL-3.0
LGPL-2.1
LGPL-3.0
AGPL-3.0
MPL-2.0
SSPL
BUSL
proprietary licenses
```

### Practical rule

If a pure MIT chain is required, avoid Apache-only dependencies.

If an Apache-only dependency is unavoidable, isolate it behind an optional Cargo feature and document that enabling it makes the resulting build subject to Apache-2.0 terms for that dependency.

## 20. Technical Principles

### Pure core domain crates

Core domain crates should avoid IO where possible.

They should be:

```text
deterministic
testable
serializable
platform-independent
```

---

### Neutral model first

File formats should not leak into domain engines.

Bad:

```text
Estimating depends directly on IFC.
```

Good:

```text
IFC parses into tpt-c-model.
Estimating consumes tpt-c-model.
```

---

### Event-first auditability

Construction projects require audit trails.

Important changes should be representable as events.

Examples:

```text
QuantityAdjusted
CostItemApplied
ScheduleRebaselined
RFIAnswered
SubmittalRejected
PaymentApplicationCertified
```

---

### Offline-first field support

Field crates should assume poor connectivity.

Design for:

```text
local SQLite storage
CRDT merge
```

## 21. License Enforcement With cargo-deny

Example `deny.toml` for a permissive chain:

```toml
[licenses]
allow = [
    "MIT",
    "Apache-2.0",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Zlib",
    "Unicode-DFS-2016",
    "Unicode-3.0",
]

copyleft = "deny"
unlicensed = "deny"

[[licenses.clarify]]
name = "ring"
expression = "MIT AND ISC AND OpenSSL"
license-files = [
    { path = "LICENSE", hash = 0xbd0eed23 },
]
```

If you want a stricter MIT-selectable chain, use:

```toml
[licenses]
allow = [
    "MIT",
    "Unicode-DFS-2016",
    "Unicode-3.0",
]

copyleft = "deny"
unlicensed = "deny"
```

Then manually review any dependency that is dual-licensed or Apache-only.

## 28. Summary

`tpt-construction` is the construction domain layer of the TPT open source ecosystem.

It uses:

```text
tpt-math
```

for numeric computation,

```text
tpt-engineering
```

for applied engineering primitives,

and provides:

```text
tpt-c-*
```

crates for construction software.

The repository remains:

```text
tpt-construction
```

The crates use:

```text
tpt-c-
```

The public license is:

```text
MIT OR Apache-2.0
```

The dependency policy should preserve an MIT-selectable chain where practical, avoid copyleft dependencies, and isolate any unavoidable Apache-only dependencies behind optional features.

Any apache only licenses, we will create an alternative from scratch.
